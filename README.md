# omarchy-sddm

The stock Omarchy SDDM login theme, with a session selector added. Installs as
a separate theme called **`omarchy-plus`**.

Omarchy's theme is deliberately minimal — a logo, a lock icon and a password
box — and it has no way to choose which compositor or session you log into. It
picks one silently. This project keeps that appearance and adds the controls
that the other stock SDDM themes (`maldives`, `maya`, `elarun`) have.

## Design: does not touch the stock theme

The stock `omarchy` theme is **left completely untouched**. This installs
alongside it and points SDDM at the new one via a single drop-in:

```
/usr/share/sddm/themes/omarchy-plus/     the theme
/etc/sddm.conf.d/zz-omarchy-plus.conf    [Theme] Current=omarchy-plus
```

Reverting is removing that one file, or `make uninstall`. There is no backup
directory and nothing to restore, because nothing was overwritten.

The drop-in is named `zz-…` so it sorts after the `omarchy-settings` files
(`10-theme.conf`, `99-omarchy-login.conf`), which also set `Current=`. SDDM
reads `/etc/sddm.conf.d/*.conf` in lexical order and later files win.

Artwork (`logo.png`, `lock.png`, `entry.png`, `bullet.png`, and the
`-failed` variants) is **symlinked** from the stock theme rather than copied.
Those files are regenerated by `omarchy-plymouth-set` when you change desktop
theme, and symlinks mean this theme follows those colour changes instead of
going stale.

## What it adds

- **Session selector** — top right, small font, following the convention of the
  stock `maya` theme. Lists every session SDDM knows about, Wayland and X11
  alike. Honours SDDM's `RememberLastSession`, so your choice sticks; falls back
  to the uwsm session when there is nothing remembered.
- **Username field** — editable and prefilled with the last user, matching the
  maldives and elarun convention. Without it there is no way to log in as an
  account other than the remembered one.
- **User switching** — only shown when the machine has more than one account
- **Power actions** — shutdown and reboot always shown; suspend and hibernate
  only when the greeter reports them available (matching `elarun`, which gates
  only those two)
- **Clock** top left, **caps-lock warning**, **status/error line**
- Keyboard navigation throughout, and RTL layout mirroring

### Not included

- **Keyboard layout selector.** SDDM's stock `LayoutBox` draws its own chrome —
  a blue focus highlight and a white arrow button — that no property can
  override, so it never matched this theme's `entry.png` fields. With a single
  layout configured it also had nothing to offer. Re-add it in `Main.qml` if you
  ever set multiple layouts in `~/.config/hypr/input.lua`.

## Targets

| Target | What it does |
|---|---|
| `make preview` | Runs the theme in SDDM's greeter test mode. Stages a throwaway copy in `/tmp`; nothing is installed. |
| `make install` | Installs `/usr/share/sddm/themes/omarchy-plus` and writes the `Current=` drop-in. Stock theme untouched. |
| `make install-no-auto-login` | Comments out `User=` and `Session=` in `/etc/sddm.conf.d/autologin.conf` if not already commented, backing it up to `autologin.conf.orig`. Without this you never see the greeter — Omarchy enables autologin on encrypted installs. |
| `make uninstall` | Removes the theme directory and the drop-in; SDDM falls back to the stock theme. |
| `make status` | Reports whether the theme is installed, whether the drop-in is present, and whether autologin is on. |

`install` and `install-no-auto-login` need root; they re-run themselves under
`sudo` and explain what they are doing as they go.

A typical first run:

```sh
make install
make install-no-auto-login
```

## Notes on SDDM 0.21

Found the hard way while building this, and worth knowing before editing the QML:

- **`Qt.DisplayRole` is not implemented on `sessionModel`** — it returns
  `undefined`. The real roles are `Qt.UserRole + N`: `+1` dir, `+2` file,
  `+3` type (`1` = X11, `2` = Wayland), `+4` name, `+5` exec, `+6` comment.
  A delegate can use `model.name`, but a plain binding must go through
  `sessionModel.data(index, Qt.UserRole + 4)`.
- Because of that, the stock theme's uwsm-preference scan never actually
  matched anything — it read `DisplayRole`, got `undefined`, fell back to `""`,
  and so always returned `sessionModel.lastIndex`.
- **A function declared inside a QML `Item` is not visible to its children's
  property bindings** (`ReferenceError: ... is not defined`). Use a `property`
  binding instead.
- **Reading a model via `rowCount()`/`data()` creates no binding dependency** —
  those are method calls. Bind against a `Repeater`'s `count` instead. A hidden
  `ListView` does *not* work for this: with no viewport it never instantiates
  items, so its `count` stays 0.
- In `--test-mode`, `sddm.canPowerOff` / `canReboot` / `canSuspend` /
  `canHibernate` are all `false`, and `userModel.lastUser` and `sddm.hostName`
  are empty strings. None of that reflects a real greeter.

## Caveat

`omarchy-refresh-sddm` rewrites `themes/omarchy`, not `themes/omarchy-plus`, so
this install survives it — but a desktop theme change will not recolour this
theme's `Main.qml` background. The two literals `#1a1b26` and `#ffffff` are what
`omarchy-plymouth-set` rewrites, so edit those by hand if you want the
background to track your desktop theme.

## Layout

```
Main.qml                 the theme (the only modified stock file)
theme.conf               stock, kept for completeness
metadata.desktop         stock, with an updated name and description
install.sh               installs as omarchy-plus, writes the Current= drop-in
uninstall.sh             removes both
disable-autologin.sh     comments out autologin
preview.sh               greeter test-mode preview, installs nothing
Makefile                 the targets above
```
